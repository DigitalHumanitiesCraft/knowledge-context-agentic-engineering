Using mistral:7b-instruct-q4_K_M local with Ollama
Mistral 7B Instruct is a 7B parameter model distributed with the Apache license mistral:7b-instruct-q4_K_M, meaning it's completely free to use. The "instruct" version is specifically fine-tuned for following instructions and having conversations.
Q4 = 4-bit quantization (compressed from original 16-bit)
K_M = A specific quantization technique that uses "type-1" 4-bit quantization in super-blocks containing 8 blocks, each block having 32 weights TheBloke/Mistral-7B-Instruct-v0.1-GGUF · Hugging Face
Result: The model is compressed to about 4.4GB in size
Context Window: Can handle up to 4096 tokens (roughly 3000 words)
RAM Requirement: About 6GB total (4.4GB model + overhead)
Hugging Face: https://huggingface.co/mistralai/Mistral-7B-Instruct-v0.3 Ollama: https://ollama.com/library/mistral:7b-instruct-q4_K_M

LLM vs. Agent vs. Workflow 
LLM A statistical text predictor. Takes text input, outputs statistically probable text based on patterns learned from training data. Intelligence or just advanced pattern matching?
Reasoning LLMA post-trained model that generates extensive "thinking tokens" before answering. Processes problems step-by-step internally and can now use tools during its thinking phase. The thinking process happens before the final output.
Agents An LLM with some autonomous capabilities. Can plan, use tools, execute multi-step tasks, and make decisions without human intervention at each step. Operates independently toward a goal.
Workflow How tasks are structured and sequenced. Can be linear, parallel, or conditional. Defines the arrangement of steps, not the underlying technology.

Model Context Protocol (MCP)

Model Context Protocol (MCP) [Anthropic]
MCP is an open protocol that standardised how your LLM applications connect to and work with tools & data sources!
It can be used in chatbots (no coding required), via APIs (coding required) or by agents.

MCP serves as an “intelligence” layer that gives LLMs analytical access to data, enabling them to interpret and understand information (either freely or through structured outputs) rather than just processing or retrieving it.
Anthropic. Model Context Protocol (MCP). https://docs.anthropic.com/en/docs/mcp
MCP: Build Rich-Context AI Apps with Anthropic. https://www.deeplearning.ai/short-courses/mcp-build-rich-context-ai-apps-with-anthropic

MCP Architecture
https://modelcontextprotocol.io/docs/learn/architecture 
MCP Host: LLM applications that access data through MCP (IDEs, agents, Chatbot, …) 
MCP Clients: One client per server (1:1 relationship)
MCP Servers are lightweight programs that each expose specific capabilities through MCP
Modular: Add/remove servers without modifying AI application
Standardized: JSON-RPC 2.0 protocol with capability negotiation
Flexible: Local (stdio) or remote (HTTP/SSE) connections
Secure: Granular permissions per connection

Deep‑Research → Literatur‑Analyse → Zotero: Workflow‑Dokumentation
Die folgende Dokumentation fasst einen Workflow zusammen, der KI‑gestützte Deep‑Research‑Prompts mit der Literaturverwaltung in Zotero verbindet. Der Workflow wurde im Rahmen der Digital‑Humanities‑Praxis entwickelt und ermöglicht es, neue Literatur zu einem Thema systematisch zu recherchieren, zu bewerten und anschließend transparent zu verwalten. Die einzelnen Schritte beruhen auf der Analyse eines parameterisierbaren Deep‑Research‑Prompts (Rollendefinition, Aufgabe, Kontext, Analyseschritte und Ausgabeformat), der mehrere KI‑Modelle ansteuert (Gemini, Claude, OpenAI und Perplexity) und die Ergebnisse anschließend in das RIS‑Format und nach Zotero überführt.

1 Überblick
Der Workflow verknüpft drei Kernbereiche:
Prompt‑Design / Deep‑Research: Ein strukturierter Prompt sorgt dafür, dass unterschiedliche KI‑Modelle (z.B. Gemini, Claude, OpenAI und Perplexity) auf vergleichbare Weise recherchieren, Zusammenfassungen liefern und die Qualität der gefundenen Quellen beurteilen.
Formatierung und Export: Die KI‑Ergebnisse werden mithilfe eines to‑RIS‑System‑Prompts in das standardisierte RIS‑Format überführt. RIS ist ein von Research Information Systems entwickelter, tag‑basierter Datensatz, der Felder wie TY (Publikationstyp), AU (Autor), PY (Publikationsjahr) und T1 bzw. TI (Titel) enthältlibrary.mskcc.org.
Zotero‑Import und Expert‑in‑the‑Loop: Das fertige RIS wird in Zotero importiert. Zotero unterstützt RIS und andere standardisierte Formate; ein Datenbankexport kann über File → Import und die Auswahl der Datei eingelesen werdenzotero.org. Danach übernehmen Fachwissenschaftler:innen die Kontrolle: Sie prüfen die Relevanz der Quellen, löschen Dubletten und strukturieren die Literaturbestände neu.
Eine schematische Darstellung des Workflows ist in Abbildung 1 dargestellt.

2 Schritt‑für‑Schritt‑Beschreibung
2.1 Parameterisierbarer Deep‑Research‑Prompt
Rollendefinition: Im Prompt wird eine Fachrolle angegeben (z.B. „Expert:in in systematischer Literaturanalyse“), die den Perspektivrahmen vorgibt.
Aufgabe: Es wird definiert, welcher Dokumenttyp erstellt werden soll (z.B. „erstelle einen wissenschaftlichen Literaturbericht zum Thema X“).
Kontext: Der Auftraggeber bzw. die Forschungsfrage wird eingegrenzt; Zeitrahmen, geografische und thematische Beschränkungen werden festgehalten.
Analyseschritte: Der Prompt spezifiziert eine Arbeitsabfolge: Datensammlung, kritische Bewertung, Synthese und Handlungsempfehlungen.
Ausgabeformat: Neben einem Executive Summary kann die Struktur der Antwort (z.B. APA‑Zitation, Zusammenfassung, Qualitätsbewertung) vorgegeben werden.
Diese Parameter machen den Prompt wiederverwendbar: Er kann mit unterschiedlichen Suchbegriffen, Methoden oder Zeitspannen befüllt werden. Eine Variation besteht darin, die wissenschaftliche Rolle (Expert:in vs. kritische Expert:in) oder die Bewertungsmaßstäbe zu verändern (z.B. ohne Peer‑Review‑Status).
2.2 Ausführung in mehreren KI‑Systemen
Verteilung auf mehrere Modelle: Der parameterisierte Prompt wird in vier verschiedene KI‑Umgebungen eingespeist: Gemini, Claude, OpenAI (ChatGPT) und Perplexity. Jedes Modell interpretiert den Prompt eigenständig, recherchiert relevante Fachliteratur, liefert eine Zusammenfassung der wichtigsten Erkenntnisse und erstellt eine qualitative Bewertung der Quelle (z.B. anhand des Peer‑Review‑Status, der Reputation der Publikation, der methodischen Robustheit, der Zitationshäufigkeit und der thematischen Relevanz).
Parallelität und Vielfalt: Durch die Nutzung verschiedener Modelle entsteht eine breite Literaturbasis; die Modelle ergänzen sich hinsichtlich ihrer Datenquellen, Suchstrategien und Zusammenfassungs‑Stile.
2.3 Generierung des RIS‑Exports
Die von den KI‑Systemen ausgegebenen Literaturangaben werden mithilfe eines to‑RIS‑System‑Prompts in einen einheitlichen RIS‑Datensatz überführt. Das RIS‑Format verwendet standardisierte zweibuchstabige Tags wie TY, AU, PY und T1/T2, um bibliografische Informationen zu kennzeichnenlibrary.mskcc.org. RIS ist weit verbreitet; viele wissenschaftliche Datenbanken ermöglichen den Export von Suchergebnissen in dieses Format, das von zahlreichen Referenzmanagern akzeptiert wird, darunter EndNote, RefWorks, Zotero und Mendeleytamu.libguides.com.
Im Export werden neben den bibliografischen Kerndaten auch die von den KI‑Modellen erstellten Zusammenfassungen und Qualitätsbewertungen als Notes‑Feld (N1 oder AB) aufgenommen. Der resultierende .ris‑Datei lässt sich leicht weiterverarbeiten.
2.4 Import in Zotero
Datei‑Import: Zotero unterstützt den Import von RIS‑Dateien. Laut der offiziellen Dokumentation können Nutzer:innen bibliografische Daten aus Formaten wie RIS, BibTeX und MODS über File → “Import…” → “A file” in ihre Bibliothek einlesenzotero.org.
Ordnerstruktur: Es ist sinnvoll, für jedes KI‑Modell einen eigenen Ordner oder eine eigene Gruppe in Zotero anzulegen (z.B. Gemini‑deep‑research‑bibliography, OpenAI‑deep‑research‑bibliography). So bleibt nachvollziehbar, von welchem Modell die Einträge stammen.
Import aus der Zwischenablage: Alternativ kann ein RIS‑Datensatz auch in einen Texteditor geöffnet, kopiert und über Import from Clipboard in Zotero eingefügt.
2.5 Expert‑in‑the‑Loop: Validierung und Strukturierung
Nach dem Import beginnt die expert‑in‑the‑loop‑Phase. Fachwissenschaftler:innen sichten die importierten Einträge, überprüfen sie kritisch und nehmen folgende Schritte vor:
Validierung der Qualität: Die KI‑basierte Qualitätsbewertung ist nur ein erster Hinweis. Expert:innen beurteilen methodische Solidität, thematische Relevanz und den Impact der Quellen anhand ihres Fachwissens.
Duplikatprüfung: Zotero erkennt Dubletten automatisch; die Expert:innen können Dubletten zusammenführen oder löschen.
Strukturierung: Einträge werden thematisch sortiert, in Sammlungen einsortiert und ggf. mit Schlagworten versehen. Notizen und Tags aus den KI‑Zusammenfassungen können angepasst oder entfernt werden.
Erweiterung / Korrektur: Fehlende bibliografische Angaben können ergänzt, fehlerhafte Einträge korrigiert werden.
2.6 Ergebnis: Kuratierte Literaturbasis
Das Endprodukt des Workflows ist eine kuratierte Literatursammlung, die aus der KI‑Recherche hervorgeht, aber durch menschliche Expertise validiert wurde. Durch den Einsatz mehrerer Modelle entsteht ein breites Spektrum an Quellen; dank RIS‑Export und Zotero‑Import ist die Verwaltung effizient, und die Expert‑in‑the‑Loop‑Phase sorgt dafür, dass nur qualitativ hochwertige und relevante Literatur verbleibt. Die kuratierte Sammlung kann als Grundlage für wissenschaftliche Publikationen, Projektdokumentationen oder weiterführende Analysen dienen.

Systematische Verluste treten jedoch insbesondere bei visuellen Elementen (Icons, Diagramme, Layout) sowie interaktiven Features (Buttons, Checkboxen) auf, was die Nutzung für design- oder layoutkritische Anwendungen deutlich einschränkt.
