## Interface contract

`docs/assets/site.css` contains the executable token values; this document records their roles and the reasons for their use. The external `UI-DESIGN.md` supplied on 2026-08-25 was evaluated as a design-system audit and has been consolidated here where it matches the accepted interface. Its proposals for a separate design document, point-only module marks, a material matrix, card-wide workshop links, fixed 768/1024 breakpoints and a top-aligned hero index are superseded by the implemented decisions above.

The type system has two semantic families. Space Grotesk carries reading text, titles and controls. IBM Plex Mono carries dates, sequence numbers, module numbers, category labels, code and prompt surfaces. The responsive scale is defined by `--text-xs` through `--text-hero`; body copy resolves between 16 and 17 pixels, section titles between 22 and 28 pixels, subpage titles between 28 and 40 pixels and the landing title between 32 and 56 pixels. Prose uses a 60-character measure. Uppercase micro-labels are reserved for metadata and never substitute for headings.

The spatial system uses an eight-pixel base from `--s1` through `--s7`, a maximum page width of 1160 pixels and section gaps that remain larger than the internal gaps of their components. The responsive rules are content-specific instead of being treated as device classes. The principal transitions occur at 1180, 1020, 860, 780 and 640 pixels. The 860-pixel boundary changes the main landing and video grids; the 780-pixel boundary changes tutorial navigation; the 640-pixel boundary produces the single-column video library and the narrowest component layouts. Every grid child can shrink through `min-width: 0`, and no component may create page-level horizontal scrolling.

Interactive elements have three visual roles. Inline links are underlined and identify destinations in prose or local navigation. Bordered actions expose an available external or downloadable resource. Dark filled controls are reserved for the primary action inside a focused tutorial surface. Unavailable formats are labelled states rather than links or button-shaped controls. A workshop in preparation retains its card title link to the information page but exposes no material actions. Focus uses the shared two-pixel turquoise outline with a three-pixel offset; hover never supplies information that keyboard focus cannot reveal.

The two public card families express different information roles. White bordered resource cards compare maintained holdings and their formats. Tinted workshop cards sit on the chronological register and combine cover, event metadata, module subset and editorial release state. Tutorial panels are sections in a continuous document and do not constitute a third card family. Video cards are subordinate items inside a module disclosure group. All media surfaces preserve their intrinsic or declared ratio; slide viewers and video previews use 16:9.

Mutable workshop and material state originates in `docs/data/workshops.json`. Mutable playlist state originates in `docs/data/videos.json`. The platform renders these sources into paired static HTML in the same maintenance step and verifies their equivalence before commit. Runtime JavaScript is not used to repair inconsistent content. HTML supplies semantic structure through one `h1`, ordered timeline lists, `time` elements, native disclosure controls, labelled metadata groups and one main-content target per page. Module colour, icon and number reinforce one another; status always includes visible text.
