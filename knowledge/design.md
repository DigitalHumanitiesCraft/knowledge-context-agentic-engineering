- **Accent**: turquoise `#0A7E7C` as the primary accent for links, active states and motif highlights; the motif line art stays turquoise-only.

## Interface contract

`docs/assets/site.css` contains the executable token values; this document records their roles and the reasons for their use. The external `UI-DESIGN.md` supplied on 2026-08-25 was evaluated as a design-system audit and has been consolidated here where it matches the accepted interface. Its proposals for a separate design document, point-only module marks, a material matrix, card-wide workshop links, fixed 768/1024 breakpoints and a top-aligned hero index are superseded by the implemented decisions above.

The type system has two semantic families. Space Grotesk carries reading text, titles and controls. IBM Plex Mono carries dates, sequence numbers, module numbers, category labels, code and prompt surfaces. The responsive scale is defined by `--text-sm` through `--text-hero`; body copy resolves between 16 and 17 pixels, section titles between 22 and 28 pixels, subpage titles between 28 and 40 pixels and the landing title between 32 and 56 pixels. Prose uses an 80-character measure, which yields roughly 75 to 90 characters per line of running text. Uppercase micro-labels are reserved for metadata and never substitute for headings.

The spatial system uses an eight-pixel base from `--s1` through `--s7`, one maximum width of 1160 pixels shared by header, main content and footer, and section gaps that remain larger than the internal gaps of their components. The responsive rules are content-specific instead of being treated as device classes. The hero and resource list remain single-column at every width. Video cards use three columns, two at 1020 pixels and below and one at 640 pixels. The remaining responsive rules adapt navigation, the footer and compact component layouts. Every grid child can shrink through `min-width: 0`, and no component may create page-level horizontal scrolling.

Interactive elements have three visual roles. Inline links are underlined and identify destinations in prose or local navigation. Bordered actions expose an available external or downloadable resource. Dark filled controls are reserved for the primary action inside a focused tutorial surface. Unavailable formats are labelled states rather than links or button-shaped controls. Focus uses the shared two-pixel turquoise outline with a three-pixel offset; hover never supplies information that keyboard focus cannot reveal.

White bordered resource cards present the maintained holdings and their formats. Video cards are subordinate items inside a module disclosure group. Media surfaces preserve their intrinsic or declared ratio; slide viewers and video previews use 16:9.

Material and Preparation links originate in `docs/data/workshops.json`; its workshop records retain provenance without generating public pages. Playlist state originates in `docs/data/videos.json`. Paired static HTML is updated with these sources in the same maintenance step. Runtime JavaScript does not repair inconsistent content. HTML supplies one `h1`, native disclosure controls and one main-content target per page. Module colour, icon and number reinforce one another; unavailable formats include visible text.
