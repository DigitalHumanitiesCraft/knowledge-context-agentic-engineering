## System values

- **Ground**: paper white as one consistent page ground, near-black typography, generous whitespace; light theme only (operator decision 2026-08-20).
- **Accent**: turquoise `#0A7E7C` as the primary accent for links, active states and motif highlights. On the tinted footer ground it reaches only 4.4:1, so footer links use the darker `--accent-on-tint` `#097472` at 5.0:1; the motif line art stays turquoise-only.
- **Identity palette**: four accents derived from the watercolor logo, orange `#C87000`, blue `#5B8FC4`, green `#7C9200`, violet `#8140B8`. The interface applies them to the five module marks (turquoise 01, orange 02, blue 03, violet 04, green 05, as implemented in `docs/assets/site.css`). Text-carrying colors must pass WCAG AA, pure marks at least 3:1.
- **Brand**: DHCraft watercolor logo (standard variant from `DigitalHumanitiesCraft/brand-assets`), set sparingly.
- **Typography**: Space Grotesk throughout with system fallback (operator decision 2026-08-20); IBM Plex Mono for prompts and code. Both are served from `docs/assets/fonts/` as Latin subsets.
- **Definitions**: a term definition opens below its term on wide viewports and stays open while the pointer moves onto it. Below 1180 pixels and on touch screens it appears as a sheet fixed to the bottom of the screen, so it never passes the viewport edge. Escape closes it where `site.js` runs.
- **Hierarchy**: at most two text levels per section, one heading and body. Preparation places its introduction and direct link before the title-slide card.
- **Imagery**: the resource marks and the Preparation title slide are the only images besides the YouTube previews.
- **Cards**: resource cards present the maintained holdings and their available formats. Video cards remain inside native module disclosure groups.
- **Chrome**: the shared header contains site identity, anchor navigation to Materials, Preparation and Videos, and the EN/DE control. The footer links the external legal notice and states the licence scope. Both pages retain the keyboard skip link, favicon and visible focus. No generic arrow-back navigation is used.
- **Current topology**: one English and one German static page contain the complete public interface. Author acceptance and publication remain separate.
- **Site identity**: the header carries one `site-identity` group with two adjacent links that have distinct destinations and distinct accessible names. The compact DHCraft logo is the only header element leading to `https://dhcraft.org`, and its accessible name names the publisher website in the page language. Beside it the complete teaching-line title is the visible site name in both interface languages and links to the language-matched landing page, resolved at the depth of its own directory, using `index.html` or `index.de.html`. The visible wordmark `Digital Humanities Craft` leaves the header, because publisher identity stays legible through the accessible name of the logo and the publisher block of the footer. The logo stays visually subordinate to the title. Both links are separate keyboard stops with their own visible focus indicator and keep at least 44 pixels on coarse pointers. The title wraps to a second line where the width requires it and is never truncated into an unexplained acronym; at narrow widths the reading order stays logo before title and the navigation may occupy its own row. The landing-page title may link to the current page and carries no `aria-current`, because the site navigation already marks the current location where one applies. ## Interface contract

`docs/assets/site.css` contains the executable token values; this document records their roles and the reasons for their use. The external `UI-DESIGN.md` supplied on 2026-08-25 was evaluated as a design-system audit and has been consolidated here where it matches the accepted interface. Its proposals for a separate design document, point-only module marks, a material matrix, card-wide workshop links, fixed 768/1024 breakpoints and a top-aligned hero index are superseded by the implemented decisions above.

The type system has two semantic families. Space Grotesk carries reading text, titles and controls. IBM Plex Mono carries dates, sequence numbers, module numbers, category labels, code and prompt surfaces. The responsive scale is defined by `--text-sm` through `--text-hero`; body copy resolves between 16 and 17 pixels, section titles between 22 and 28 pixels, subpage titles between 28 and 40 pixels and the landing title between 32 and 56 pixels. Prose uses an 80-character measure, which yields roughly 75 to 90 characters per line of running text. Uppercase micro-labels are reserved for metadata and never substitute for headings.

The spatial system uses an eight-pixel base from `--s1` through `--s7`, one maximum width of 1160 pixels shared by header, main content and footer, and section gaps that remain larger than the internal gaps of their components. The responsive rules are content-specific instead of being treated as device classes. The hero remains single-column at every width, and its H1 is capped at 32 characters so the title takes two lines on wide viewports. Video cards use three columns, two at 1020 pixels and below and one at 640 pixels. The remaining responsive rules adapt navigation, the footer and compact component layouts. Every grid child can shrink through `min-width: 0`, and no component may create page-level horizontal scrolling.

Interactive elements have three visual roles. Inline links are underlined and identify destinations in prose or local navigation. Bordered actions expose an available external or downloadable resource. Dark filled controls are reserved for the primary action inside a focused tutorial surface. Unavailable formats are labelled states rather than links or button-shaped controls. Focus uses the shared two-pixel turquoise outline with a three-pixel offset; hover never supplies information that keyboard focus cannot reveal.

White bordered resource cards present the maintained holdings and their formats. Video cards are subordinate items inside a module disclosure group. Media surfaces preserve their intrinsic or declared ratio; slide previews and video previews use 16:9.

Material and Preparation links originate in `data/workshops.json`; its workshop records retain provenance without generating public pages. Playlist state originates in `data/videos.json`. Paired static HTML is updated with these sources in the same maintenance step. Runtime JavaScript does not repair inconsistent content. HTML supplies one `h1`, native disclosure controls and one main-content target per page. Module colour, icon and number reinforce one another; unavailable formats include visible text.
